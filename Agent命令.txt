Git 与 GitHub Agent 提示词手册

    Git 分区与基本生命周期
        Clone   远程仓库复制到本地工作区
        Commit  工作区提交到本地仓库
        Push    本地仓库推送到远程仓库
        Pull    远程仓库同步到本地工作区

    项目初始化与首次推送
        “把当前文件夹初始化为 Git 项目并推送到 GitHub 上 排除不需要的 node_modules 和日志文件”

    版本提交管理 (针对某次特定提交 ffe02fa25ff9eb3f9cc931961809d07f32c8b330)
        回退版本
            “把仓库还原到 ffe02fa25ff9eb3f9cc931961809d07f32c8b330 这次提交状态 后面的所有改动都不要了”
        撤销提交
            “把 ffe02fa25ff9eb3f9cc931961809d07f32c8b330 这一次提交安全地撤销掉 其它保持不变”
        比对改动
            “比较一下 ffe02fa25ff9eb3f9cc931961809d07f32c8b330 和 另一个提交 看看这两个版本改动了什么内容”

    分支开发流
        新建与合并
            new branch, merge, delete branch
        拣选合并
            “帮我把分支中 ffe02 和 yye03 这两个提交合并进主干，其他的提交不要”
        暂存修改
            stash, pop stash

    多工作区并行开发 (WorkTree)
        创建分支工作树
            “复制主干文件夹并创建一个WorkTree 让我能够并行运行或对比这两个物理文件夹 保证改动互不影响”
        合并分支并清理
            “把WorkTree的修改合并回主干 合并完后删除这个WorkTree和对应的分支”
        解决冲突
            “把这两个工作区合并 如果遇到冲突请列出来让我选择如何处理”

    多人协作与开源贡献
        避开冲突黄金法则
            在向原项目提交 Pull Request 之前 先把原项目的最新代码同步到自己的本地分支 解决冲突后再提交
        同步母项目最新改动
            “母项目地址是 https://github.com/stephentangzizhong/test-remote.git 
            请把母项目最新改动合并进当前分支 如果有冲突让我选择如何处理”
